Geohod Quest · Player input

Answering without losing the button

When the player taps the answer field, the on‑screen keyboard rises and the «Ответить» button disappears behind it. Below is the live diagnosis, a keyboard simulator, and three ways out — compared under the keyboard, on both platforms.

The bug

The submit button is stacked below the input in a frame that is overflow:hidden. Lift the input above the keyboard and the button goes behind it.

Root cause

interactiveWidget:'resizes-content' is honored on Android, ignored on iOS. The layout never resizes for the keyboard, so a control below the field can't survive.

It's a class

The same shape hides the «Я на месте» note action and the report sheet's «Отправить». Fix the structure once, not three symptoms.

Recommendation

Ship 1a now. It deletes the root cause — submit no longer lives below the field — with a CSS‑only change plus an enterKeyHint, and it fixes iOS without the visualViewport edge cases that make 1b fragile.

Adopt 1c as the input system — answer, note and report — where keeping the error and hint in view while typing actually matters. Treat 1b as a last resort: the most keyboard‑listener JS for the least gain over 1a.

The 1a diff, in code
  • wrap field + submit in a <form onSubmit>
  • field + submit on one flex row
  • enterKeyHint="send" · inputMode
  • autoCapitalize/Correct="off"
  • guard e.isComposing before submit
