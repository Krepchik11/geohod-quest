## 4. Rebuild: Proposed Refinements (100% Compliant with Locked; Improves Robustness/Maintainability)

**Stay 100% inside locked (verbatim):** Client full local validation against *its* downloaded snapshot (03:17-19,36-37). **NO correctness re-val on sync** (03:20,53; 08:7-8,17; "server records... local... no re-validate"). New attempts/downloads = latest published at that instant (03:21-22,57; 01:160,04:76). Old attempts frozen to *their* snapshot (03:22-23,61-63,118; "old attempts + their bundles stay frozen"). Sync = record submissions + client-claimed outcomes (is_correct etc.) + per-version analytics + coin reconciliation (03:46-56,66-78; "recording only + coin master-balance reconciliation... + per-version analytics"). ~5MB (03:35,57; 04:57,83). Physical = explicit player_confirmed (03:40,89-98; 08:21). Multiple independent attempts (01:75,03:104). Grant required (02,05). Retention for re-dl of historical (implied 03:122,147; AN02 locked). Idempotent, eventually consistent (03:111). Client as judge for version (08:13). Plain strings acceptable for v1 (08:32-36: multiline, basic membership, normalization later, cheating deprioritized).

**Refinements (targeted, minimal, justified by deconstruct/expose + siblings):**

**A. Bundle format (specific rec — stick closer to plain with strong client tests + optional hashed audit layer; reject full "plain rejection" for v1):**
- Core (locked-compliant): Snapshot bundle = { snapshot_id (or quest+version monotonic), published_at, game_steps: [ {pos, kind/completion: {mode:'physical'|'answer', acceptable?: string[] (plain from constructor multiline at publish time, trimmed? no — exact as authored), allow_note?}, supporting: {gift?:{coins:number (snapshot-frozen), narrative}, hint?:{cost, reveal_geo, reveal_content}, ...}, rich_content (RU texts, media refs, geo display-only), ... } ], integrity: { hash: sha256(canonical whole), ... }, media_manifest? }.
- "Plain strings" for acceptable (exact per 08/03). Client: basic membership (exact or contains per locked MVP; trim? author responsibility via preview). "Protected form" (04:72) interpreted as "the list as snapshotted + integrity hash on bundle" (not hashed answers yet).
- **Strengthen without violating:** (1) Constructor (ANALYZE-07/04:59) *must* have parsed answers preview pane (show list, count, warn blanks/dups/trailing; live test submit box that runs *exact client match fn* against the list — "save+test player" is acceptable but editor test catches 80% before publish). (2) Bundle includes `matcher_version: "basic-membership-v1"` (or simple descriptor) for future evolution without breaking old frozen. (3) *Optional v1+ audit layer (not default, not blocking):* per-snapshot salt (generated at publish, delivered in bundle); server also stores `acceptable_hashes = [hash(salt + canonical(a)) for a in list]` alongside plain (for background analytics only). Client *may* (opt-in) compute receipt {submitted, claimed_is_correct, step_pos, snapshot_id, submitted_hash_under_salt, receipt_sig?} on answer events. Sync uploads receipts as *audit metadata only* (server stores with fact; background job can flag "claimed correct but hash not in frozen set for this snapshot" for author dashboard — *never* overrides recorded is_correct or affects player UX/coins/attempt status). This gives "tamper detection" post-facto (report value) without v1 "plain rejection", without critical-path re-val judgment, without changing client happy path. Plain + strong tests (editor live match + property "for any list + any input, client match == recorded is_correct on replay") is KISS for MVP. Hashed acceptable sets + mandatory receipts = post-MVP (when 21→more quests or cheating evidence).
- Why better: 100% locked (plain in bundle for client val; server never re-computes is_correct from live or even from frozen for player outcome).
