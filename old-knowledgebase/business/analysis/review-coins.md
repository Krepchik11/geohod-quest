## 4. Rebuild: Refinements + Recommended Hybrid (Fits Locked + GAMSTEP/Constructor Cross Exactly)
Best fit for locked (earnings *only* from snapshot gifts/completions; per-attempt spends *tracked*; master reconciliation on sync; offline *local*; no admin/real$ v1) + cross (gift amounts *frozen in snapshot GameStep* at publish; per-step in completion/supporting; sync payload = StepCompletions w/ coins_spent_on_hint per 03; constructor enters gift_coins number per step in gift supporting; rich content primary, small data for gift/hint).

**Preferred base: Immutable facts (report's V3), refined as "CoinFact ledger" (narrow, not full events domain). Hybrid with V1 materialized projection + V4 skepticism for dedup.**

**Refined model (explicit policy + shapes):**
- **Source of truth:** Append-only CoinFact rows (or polymorphic in a narrow ledger): 
  - id (server), player_id, attempt_id (for attribution), quest_id, snapshot_id (the bound version), step_position (or step_snapshot_ref), fact_kind: 'GIFT' | 'COMPLETION_BONUS' | 'HINT_SPEND' | 'LEGACY_CREDIT' | 'CORRECTION', amount: signed int, cost_or_gift_value (frozen copy or ref), idempotency_key (e.g. attempt_id + step_position + kind or client_uuid), created_at (server), source (sync|import|correction).
- Spends: 1:1 with StepCompletion (denorm coins_spent_on_hint + hint_revealed on the completion row for the attempt+step; *also* emit a HINT_SPEND fact for audit). No separate "wallet" mutation.
- Earnings: Server-only on authoritative insert of qualifying StepCompletion (gift step: amount = the GameStep.gift.coins from *that completion's snapshot* (frozen at publish via constructor); terminal: COMPLETION_BONUS if no prior for (player, quest)).
- Projection: Player.master_coin_balance = SUM(all CoinFact.amount for player) [materialized view or on-read fold + periodic checksum job against facts]. QuestAttempt.total_coins_spent = SUM(its StepCompletions.coins_spent_on_hint) or fold of its HINT_SPEND facts.
- First-class idempotency + unique: (player_id, quest_id, fact_kind, step_position?, snapshot_id?) for gifts/bonus; (attempt_id, step_position) for spends. INSERT ... ON CONFLICT DO NOTHING or tx + existence check for bonus.
- No direct Player.balance mutation ever (even for import: legacy is a LEGACY_CREDIT fact).

**Specific policy recs (to lock in 08 + 01/03 updates):**
- **First-only bonus scope:** Per (player, quest) ever (global, not per-attempt, not per-version). Matches old Getting_5... intent (list of quest refs to prevent farming the *same quest*). Use narrow unique fact or constraint on (player_id, quest_id, 'COMPLETION_BONUS'). Versions: completing v1 "claims" the bonus for the quest; v2 completion does not re-award. New gift steps in v2 *can* award (different snapshot/step).
- **Replay re-earn gifts?:** NO for replays/resets on the *same* quest snapshot (or same quest lineage). Gift award is once per (player, quest, step_position_in_its_snapshot) — first time a qualifying StepCompletion is authoritatively recorded for that player/quest. Replays (new attempt or reset+re-complete) get no additional gift coins (incentivizes first mastery; hints still cost on replays to "practice"). If new version adds a gift step, it is a *new* (snapshot, step) → earns. Conservative to prevent "farm easy quests for hint money on hard ones via replays". (Alternative if stakeholder wants replay incentive: award gifts *per attempt* but still dedup bonus; report's "if policy allows". Recommend first-only for gifts too, grounded in old list hack for the 5-coin.)
- **Cost per hint:** Configurable per-step via GameStep supporting `hint: { cost_coins: number (default 1, author-editable in constructor 0/1/5/etc.) }`. Snapshot-frozen. Client local: "can buy?" = local_projected >= this_step's snapshot cost. Variable costs are *supported* by locked ("per-step") + 01/04 data shape; "lightweight" preserved by showing cost in UI before buy (from bundle). Old probably fixed-1; new makes it explicit + author-controllable without changing model.
- **"Per-attempt vs global" resolution:** 
  - Spends: *per-attempt tracked* (StepCompletion.coins_spent_on_hint + QuestAttempt.total_coins_spent aggregate = fold of its spends). Affects global.
  - Earnings: *global* (projected to Player; emitted on StepCompletion record regardless of which attempt "produced" the gift/completion, but attributed via attempt_id for audit).
  - Cross-attempt: Earn in attempt A (global +), spend in attempt B (global -) is allowed and normal (cross-quest economy). Per-attempt total spent is *informational* ( "this playthrough cost me X coins on hints").
  - Matches 01 exactly (both fields) + 03 ("per-attempt, per-step" + "master player coins = sum... minus spends") + old (global Balance_coin + per-card Buy_hint flags).

**How it interacts with offline (local projection from snapshot + local completions):**
- Bundle (from publish via constructor): full GameStep seq with supporting.gift {coins, narrative} + hint {cost_coins, ...} frozen at that snapshot.
- Local play (03): per-attempt local state (completed steps, coins_spent per step or running local_spent, local_projected_balance). On reach gift step or terminal congrats: locally project +gift.coins (from *this* snapshot in bundle), update UI balance. On buy: if local_projected >= step.hint.cost_coins, set local coins_spent += cost, reveal (geo + content), deduct from local projected. Pure client. Gifts/earns "pending" visible locally.
- On sync (03 payload): upload StepCompletions enriched with coins_spent_on_hint (the per-step fact), hint_revealed, (optional) local "I think I earned X from these gifts/terminal".
- Server: for each new completion, if the step (per attempt's snapshot) has gift.coins >0 or is terminal, *emit CoinFact* (idempotent by key including snapshot_id + step_pos + kind; use the *frozen* amount from the completion's snapshot data or referenced GameStep version). Record the spend fact/denorm. Recompute authoritative projection. Return: true current balance, list of corrections (e.g. "step 7 spend duplicate/not applied; balance +1 vs what you thought; some reveals un-done if strict policy"), accepted StepCompletions.
- Correction (03): client applies to local attempt state + cached global balance. "Syncing..." + "balance corrected" UI. Versioned: old bundle's gift values used for local *and* what server emits.
- Long offline: works (provisional local), eventual authoritative. Multi-device: facts union by key (first recorded completion "wins" the earn/spend fact for that (attempt,step); others correct on next load).
- Fits locked 03 perfectly; no change to payload shape (coins_spent_on_hint is the spend carrier).

**Constructor interaction (entering gift_coins in step):**
- Per 04/01/ blueprint (refined): in step editor, when gift supporting enabled (or "Gift" behavior): number input for coins (presets 0/1/5/10 from old Gift_Coins/5-coin patterns + countCoinMadeIt), + narrative text. Validation: non-neg int.

- No "steps_for_accruing_coins_" equivalent needed: on server record of gift StepCompletion, the fact exists (query "rewards where quest+version+attempt" replaces the old custom state accumulator).
- Strengthened gates (per constructor variants + synthesis): preview pane shows "this step awards N coins on completion" + "hint costs M"; publish warning if gift on non-terminal without narrative, or cost=0 on hint step, etc.
- Matches cross: "gift_coins entered per step, snapshotted at publish"; "publish must emit the exact snapshot shape (including frozen gift amounts)".
