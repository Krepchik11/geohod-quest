## 1. Deconstruct: Exhaustive Edge Cases, Race Conditions, Bottlenecks, Best-Practice Violations for Real Quests

**Sources attacked (grounded, not invented):** Locked 00/03/06/08 + 01/04/07/09 + discovery (556 steps/21 quests/~26.5 avg from record_counts + data_types; page_constructor media as URL refs: Video_link/Image_link/Hint_Image; no offline/PWA mentions; mutable; answer_card flags only no submitted; 1,163 WFs assumed connectivity); cross ANALYZE (bundle size from GAMSTEP/constructor rich content + answers[] + supporting gift/hint/media/geo; client projection; event facts for sync; v0 legacy snapshots at import; 5MB target repeated; "video bloat"/"storage pressure on low-end"/"SW/IDB quirks" called out in FINAL as risks; "core guarantee" prelim; no quota strategy beyond "warn"/"comfortable"); real-quest implications (location physical quests = long play sessions, battery drain, multi-device (phone while walking + tablet at home), geo display/hints critical but "display only" + "no GPS reliable offline"; videos 10-30s "sometimes" but "many?" across 25+ steps per quest compounds 5MB; media cache eviction by OS/browser under pressure; mid-download on flaky mobile; low-end Android (small quota, aggressive SW kill, weak IDB perf, no reliable background sync); corrections visibility (player on device A sees "correct" local, device B syncs correction → surprise un-reveal or balance fix); long quest (25+ steps) offline UX (progress save every step? resume exactly? battery for map+media+local match); old zero design = the baseline to never repeat.

**Categories (exhaustive):**

### Quota, Bundle Size, Mid-Download/Play Failure (5MB "highly feasible" attacked)
- Quota hit *mid-download* of 5MB + videos (after partial media cache): partial bundle? Can player start play with what they have (violates "full offline")? Or fail hard (bad UX for paid content)? No strategy in locked.
- Video in 5MB: "10-30s but many?" (discovery: "sometimes used"; constructor notes "must be cacheable"; no counts/sizes in parsed/probes — only URL refs. One 20s video ~few MB compressed; 3-5 across 25 steps + images + structured + answers lists + geo = easily 5-8MB real. "Highly feasible" claim ungrounded without composition data.)
- Accumulated quests: player owns 5-10 (lifetime grants); each 5MB + media = 25-50MB+ pressure on low-end device (typical mobile quota per-origin ~50-100MB but shared with other apps + OS eviction). "Warn if many" is not a strategy.
- Mid-play quota (e.g. during long quest, additional media load or SW cache pressure): local state (progress, coins projection) survives? Or evict bundle mid-attempt → stuck (violates full offline + "no mid-play failure").
- Client quota API (navigator.storage.estimate()) + pre-dl check: not specified. "Explicit fail with size estimate" in FINAL prelim is good start but not implemented in locked.
- Bundle size from constructor/GAMSTEP: rich per-step content (main_text/place etc. RU) + answers lists (multiline → string[] ) + supporting (gift coins, hint cost, media refs, geo) + version/hash. Structured ~KB; media dominates. Real 556 steps validation needed (repeated rec across ANALYZE).

### Low-End Device (IndexedDB limits, SW failures, no GPS reliable offline for geo display, battery)
- IndexedDB: per-origin quota + perf limits on low-end (slow writes for long 25+ step attempt state + event log per ANALYZE-05 rec; complex objects for snapshot + completions). SW may kill on memory pressure mid-play.
- Service Worker failures: install/activate race, fetch failures for bundle/media on flaky net during dl, cache put failures under quota, no background sync reliable on low-end. "Full offline" after partial SW fail = broken.
- No GPS reliable offline for geo display: locked "geo display only" + "show on map" for hint spend. On low-end/no-GPS device or airplane mode, map pins still render (static from bundle) but "my location" fails or stale. UX for "GPS unavailable offline"? Hint reveal still works (local coin deduct + show pin from snapshot).
- Battery for long quest (25+ steps, real-world location play): map rendering + local match on every answer + coin projection + media decode (video) + SW background = drain. No battery-aware (e.g. defer non-critical cache)? Resume after kill?
- SW + Cache API + IDB combo on low-end Android/iOS: common failures (cache quota, IDB version bumps on app update nuking data, persistent storage requests ignored). "Test on real devices" in FINAL but no plan in locked.
- Low-end graceful: text-only fallback? (per FINAL prelim). Core (narrative + structure + key images) vs full media.

### Multi-Device UX (different local states, corrections visible?, "which state is real?")
- Two devices, same player/attempt/snapshot, both offline: Device A advances to step 7, spends 2 coins on hints (local projection shows balance -2, reveals). Device B advances to step 5 (different path or same), spends 1. On sync order A then B: events union (per ANALYZE-05 rec) → full progress, net -3. But "corrections visible?": if overdraft (prior balance stale), server emits correction event → one or both devices show "balance corrected; hint on step X un-revealed" on next load. Player confusion: "I bought it offline, why is it gone?"
- Different local states visible? "Continue" on device A shows its pending; after sync, re-project shows merged + any server corrections (explicit banner per rec). "Last-write or union" (locked 03) insufficient (improved in recs but UX of divergence not specified).
- Corrections: visible (banners + re-render of attempt state + coin delta log). Per ANALYZE-01/05: honest pending + "balance corrected" + audit trail. No magic.
- "Which is real?": server facts + projection = authoritative on sync; local always provisional until acked. UI must surface "X pending sync" + "last synced Y".
- Legacy import multi-dev: old answer_cards (no device concept) become one legacy attempt; new multi-dev on v0 or later.

### Long Quest (25+ steps) Offline UX (progress save, resume, battery)
- Progress save: every step (physical confirm, answer submit local match, hint spend, gift claim, advance) must persist locally (IDB or equiv) immediately (crash/kill mid-25-step = lost hours). Resume exactly (current pos + revealed hints + spent coins + submitted answers + local is_correct per snapshot).
- Battery: real location quest = walking + phone on + map + occasional video + local compute. 25+ steps could be 2-4+ hours. Low-end drain faster. No spec for "save + allow background or low-power mode".
- Resume after force-kill or clear: re-dl bundle if retained (per ANALYZE-02) + replay authoritative events (per recs) or local state. "Full offline" means must work without net for the *entire* sequence.
- 556 steps / 21 quests avg ~26.5 confirms "many steps" real (not hypothetical).

- Progressive: on-demand fetch when online + cache, but guarantee offline play without them.

### Sync Pending / Corrections / "You are offline" UX (should vs must)

### Other (PWA Install, Multi-Quest, Edge Recovery, Old Contrast)
