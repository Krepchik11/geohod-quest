## Decisions

**State management: append-only immutable facts array + useReducer + pure project* on render (derived).**  
Facts (from shared Fact) are the source of truth; every user action (physical_confirm, answer_submitted, hint_purchased on spend, gift_claimed on reach/advance, attempt_completed on terminal, feedback_reported, navigator_used) appends exactly one (or paired) fact with coins_delta from snapshot, local_is_correct claim, device_id, step_position. Reducer: `(state, {type:'append', fact}) => ({...state, facts: [...state.facts, normalizedFact]})`. Balance/revealed/completed = projectBalance(facts) / projectState(facts) computed in render (small N=steps, cheap). Persist via useEffect([facts, stepIdx], () => localStorage.setItem(`quest-player-${goldenId}`, JSON.stringify({facts, stepIdx, ts: Date.now()}))). On mount: load/parse/validate for this golden (else reset to []).  
*Rationale (why over mutable state or single derived store):* Matches blueprint/TECH "event-sourced ... facts as unifying primitive", "client maintains a local event log + identical projection", "deterministic merge", SPEC "append-only immutable facts". Survives all races/edges from PLAN (multi-wrong, overdraft attempt, reload mid-hint, gift timing). Goldens provide exact expected_facts for assert (replay produces identical). Enables future sync: extract pending from log, POST idempotent, receive+append correction facts, re-project (no client state rewrite). Alternative considered: mutable currentAttempt + facts log only for audit (fragile races on spend concurrent with gift, harder projection fidelity, violates "no mutable attempt state" in PLAN risk mitigation). useState + manual concat would work but reducer makes append semantics explicit + testable in isolation.  
*YAGNI note:* No global store/context (overkill for single-player view); no persistence lib.

**Component architecture: RSC page shell + small focused 'use client' subcomponents (discriminated by template, <100 LOC each); co-located under app/quest/. Strict import of all pure logic.**  
- `app/quest/page.tsx`: async RSC (or client with useSearchParams). Loads snapshot = getSnapshot( search.get('golden') || 'mystery-fortress-v1' ) via goldens (static import works), renders server chrome + passes snapshot to `<QuestPlayerClient snapshot={snapshot} />`.
- `QuestPlayerClient.tsx` ('use client'): holds reducer state (facts, stepIdx, showPopup, simOffline, bonusAnim), useEffects for persist/load + bonus trigger, handlers (appendFact, advance, spendHint, openFeedback, handleNav). Renders <CoinDisplay balance={projectBalance(facts)} />, <OfflineBanner simOffline={simOffline} onToggle=... onSimSync=... />, <StepIndicator ... />, and delegates to `<StepRenderer step={steps[stepIdx]} onAction={...} revealed={projectState(facts).revealedHints.includes(...)} facts={facts} />` + Feedback menu always visible.
- `StepRenderer.tsx` (or inline switch in client for YAGNI): if (template==='first_screen' || supporting.is_start) <FirstScreenView ... onConfirm={handlePhysical} />; else if (completion.mode==='physical' || template==='task_no_answer') <PhysicalTaskView step=... onConfirm={...} onNavigator={handleNav if supporting.navigator} />; else if (mode==='answer') <AnswerTaskView ... /> (contains <AnswerForm value=... onSubmit={v => { const correct = isAnswerCorrect(v, acceptable); append({type:'answer_submitted', submitted_value:v, local_is_correct:correct, coins_delta:0, ...}); if (!correct && supporting?.hint) { setShowWrong(true); return; } claimGiftIfAny(current); advance(); }} /> ); else <ContinueView onConfirm=... for terminal />.
- `PhysicalConfirmButton.tsx`: uniform <button onClick={e => {const note=allow_note? prompt or input:''; append({type:'physical_confirmed', note, local_is_correct:true, coins_delta:0}); claimGiftIfAny(); advance(); }}>{button_text || physical_action?.confirm_label || 'Подтвердить'}</button> + optional note field.
- `AnswerForm.tsx`: controlled input + submit; live? (on change could preview but YAGNI; on submit does the isAnswerCorrect call + logic above). Re-uses exact imported fn.
- `WrongHintPopup.tsx`: modal shown only after wrong on answer step that has hint. Shows "Неверно. Потратить ${cost_coins} монет за подсказку?" (per SPEC "immediate popup"). onSpend: if (projectBalance(facts) >= cost) { append({type:'hint_purchased', step_position, coins_delta: -cost, ...}); setRevealedLocal(true); close(); } (no overdraft). Cancel: just close (no fact, player can retry answer).
- `NavigatorButton.tsx`: if (supporting?.navigator && (template==='task_no_answer' || completion.mode==='physical')) <button onClick={() => { append({type:'navigator_used', ...}); window.open(`https://maps.google.com/maps?q=${lat},${lng}`,'_blank'); or in-app stub map }} >{label || 'Открыть навигатор'}</button> (gated by hint_only etc per supporting but show always if present for v1).
- `FeedbackMenu.tsx`: global (header or floating "☰" or link "Оставить отзыв" on every view). On click: const note = prompt('Опишите проблему/отзыв (прикрепится к текущему шагу):'); if(note) append({type:'feedback_reported', step_position: cur, note, coins_delta:0, local_is_correct:true, ...});
- `CoinDisplay.tsx`, `OfflineBanner.tsx`, `BonusAnimation.tsx` (on gift_claimed or attempt_completed: if supporting.bonus_animation, show +coins visual + speechSynthesis.speak if avail + confetti stub; timeout auto-hide).
- Helpers in same files or small utils (no barrel).

## Risks / Trade-offs

[Gift claim auto-insertion timing to match happy golden (no action recorded at gift step)] → Mitigation: explicit logic in both replay test and player advance ("if step has gift and not yet claimed in projection, append on reach/after prior complete"); test will fail loudly until exact. Document in code + golden notes. If future real exports differ, update golden first.

[Extending shared Fact type in this change (touches prior shared-model-goldens cap)] → Mitigation: purely additive union + no behavior change to project fns or existing goldens/ctor/tests. Proposal explicitly listed no "Modified Capabilities" (no req change). Future refactor to split Fact kinds is non-breaking. If OpenSpec apply requires delta spec, add minimal one.

[Local-only facts + LS (no real sync/races with server yet)] → Mitigation: design + TDD replay prove projection contract and append-only semantics now; shape is identical to what sync will use (idempotency via device+ts+pos+type). "simulate sync" exercises the banner/correction UX path. Per PLAN risk "New mid-quest state creates additional sync races" — facts + pure project is the mitigation. Full backend next slice.

[One interactive client tree for player (potential re-render/perf on fact append)] → Mitigation: small subcomponents + derived state in render (no memo overkill yet) + useReducer (batched) + react.md rules (narrow effects, functional updates, defer). Quests small (N steps << 100). Profile later if needed.

[Dupe risk with ctor (inline match, god comp)] → Mitigation: player strictly imports; tasks include "replace ctor's inline isMatch with import from shared-model + remove comment" (drive-by DRY, small, improves the "Save+test" link UX). Self-crit: we will not repeat the violation.

[LS contract for future multi-device] → Mitigation: facts + device_id + local_ts make union/merge natural later (as in TECH). Key scoping by golden/snapshot prevents version drift.

[No bundle size / real media yet] → Mitigation: YAGNI; stubs + goldens prove flow. Real est + 4-role in ctor+player together when assets available (per PLAN Phase1).

Trade-off YAGNI vs best-practice: chose minimal LS + simulate over premature full offline PWA stack or packages/ (current monorepo DX is clean skeleton; adding would violate YAGNI until duplication or failing test forces). This enables future slices perfectly (facts shape, StepRenderer reuse in ctor for previews, snapshot load path, local log ready for idempotent append).

Enables: ctor test link works immediately; goldens fidelity proves "frozen snapshot + client auth" before any backend; small comps + shared imports set pattern for marketplace etc.; local contract matches TECH/SPEC for sync.
