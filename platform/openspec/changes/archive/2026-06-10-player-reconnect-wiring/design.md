## Goals / Non-Goals

**Goals:**
- Make "simulate sync" real (when !simOffline): capture current facts as batch, POST with attempt_id derived + snapshot_id=goldenId to the live backend contract, on 2xx apply response.corrections (append to local facts via existing appendFact path after normalize), re-project (derived), LS auto-saves via existing effect, update banner (clear pending, show "synced" or "balance corrected by X" temp if corr delta !=0); authoritative projected in resp used for debug/banner parity check but re-project is source.
- Support demo reconnect/multi "reconnect" for same attempt: attemptId = `demo-${goldenId}` (fixed per golden, generated/persisted in LS saved payload so reloads + "Save+test" target consistent attempt for idempotent reconnect tests).
- Corrections applied locally without data loss/double facts: only append corrs (server already deduped accepted; local had the pending sent); normalize server corr shapes (missing local_is_correct/submitted_value etc.) to shared Fact by filling safe defaults (local_is_correct:true, submitted:null etc) so appendFact + projectors work.
- Preserve full fidelity + TDD contract: goldens/replay unchanged for happy; extend replay (or harness) with reconnect sim: build facts from golden actions, "reconnect" by applying mock {corrections: [balance_corrected example from overdraft scenario], ...}, assert corrections folded, final project authoritative, LS roundtrip post-apply still matches.
- Offline sim fully preserved + orthogonal: simOffline toggle still short-circuits real POST (shows sim alert or equivalent), btn label stays "simulate sync", all prior flows (4 templates, popup ONLY on wrong, gift timing for "МИХАЙЛО ПУПИН", feedback/nav any time, ctor link, complete screen) untouched.
- Small focused per react.md + SOLID/DRY/KISS/YAGNI: enhance QuestPlayerClient (add 1 handler + minimal reducer cases + 1 normalize helper + attemptId in state/LS) + OfflineBanner (add 3 optional props: pendingCount, isSyncing, corrMessage; keep <25 LOC); no new files/god comps; native fetch (no pkgs); all project*/Fact 100% imported; derived always in render; narrow useCallback/useEffect deps; explicit ifs.
- Error/robust: network fail -> keep all local facts + set error banner "sync failed, still offline (local authoritative)"; no facts lost; multi-reconnect safe (idemp server); during POST allow concurrent appends (new facts stay local, only corrs merged on return).
- Verifiable: after impl, replay green (incl new corr cases), frontend build+lint clean, manual via "Save + open in real player as test user" (ctor) + play offline (toggle) + click sync (backend on localhost:8080) shows corrections if any (e.g. force overdraft case) + authoritative bal, LS survives.
- Enables PLAN "on reconnect" without bloat; closes client/server facts loop.

**Non-Goals:**
- No real auth, grants, attempt creation, or AccessGrant enforcement (demo attemptId + golden always accepted by current backend; YAGNI per PLAN cuts + prior artifacts).
- No full PWA (SW, Cache, IDB assets, install); no bundle fetch; LS only for state (as before).
- No new packages, no config changes (hardcode API_BASE='http://localhost:8080' with comment for demo; tasks note "run backend separately").
- No auto-retry, backoff, or conflict resolution UI beyond simple banner ("balance corrected", "sync failed"); no "corrected" deep modal or per-fact highlighting (reuse existing completion UI + debug facts list).
- No change to reducer core or gift/advance timing (reuse claimGiftIfNeeded etc).
- No persistent "lastSynced" marker or delta pending (send full facts array every time; server natural-key idemp makes it correct + simple; YAGNI until perf proven).
- No update to facts-sync or shared-model-goldens specs (additive Fact only; projectors/goldens behavior identical; prior archived noted this).
- No backend edits, no rust tests, no deep version mismatch UI (if resp snapshot differs, still apply corrs + re-project; banner note optional).
- No god components or barrel imports; no useContext for sync state.

## Decisions

**Decision: attemptId derivation + LS roundtrip (fixed `demo-${goldenId}` per golden, persisted in saved payload alongside facts/stepIdx).**  
Rationale: No attempt registry yet (YAGNI per briefing/non-goals); client-generated per PLAN/TECH for demo. Fixed per-golden ensures "Save + open in real player" + offline play + multiple reconnects all target same logical attempt for idempotent tests + multi-device sim (different devices would use different but for single-player demo fixed is perfect). Store in LS object {facts, stepIdx, attemptId} so reloads resume same attempt (critical for "reconnect" UX after close tab). On first mount if no saved attemptId, set the demo value. In sync handler: const attemptId = state.attemptId || `demo-${goldenId}`; POST to `/api/attempts/${attemptId}/facts`. Server accepts any string id.  
Alternatives rejected: randomUUID() every time (breaks reconnect demo, each "reconnect" new attempt); global const (cross-golden contamination); omit from LS (reload = new attempt, less realistic for PLAN reconnect).  
Survives: idemp server, goldens replay (device_id separate), future real grants (attemptId can be swapped for real one later).

**Decision: always send full current state.facts as the batch (no "pending since last sync" delta or acked marker); on success apply *only* response.corrections (not accepted).**  
Rationale: Server is authoritative for dedup (natural key = device_id + step_position + type + submitted_value + coins_delta + note); sending full log is always correct (reconnects/multi-device union), matches "upload pending facts" + "long offline queue" scenarios in facts-sync spec. Capturing at click time (`const pending = [...facts];`) + POST, then on success only for (const c of resp.corrections) { appendFact(normalize(c)); } ensures: (a) no double in local log (accepted were already here), (b) concurrent appends during flight are kept (new local facts + corrs appended), (c) re-project after gives authoritative (projectors order-indep for bal/sets). Use existing appendFact + reducer concat + derived project (no replace of facts array). LS effect on facts fires automatically. projected in resp can assert bal match or show in debug.  
Natural key dedup on client side not added (YAGNI; trust server accepted list + only fold corrs; projectors converge anyway).  
For corr normalize (toClientFact): map BalanceCorrected/Version... to {type: raw.type, step_position:.., coins_delta:.., note: raw.note||null, device_id: raw.device_id, submitted_value: null, local_is_correct: true } (safe defaults; corr facts have no "claim" semantics). VersionMismatch also folded (0 delta). This makes appendFact accept it and projectors (which sum any coins_delta, ignore non-completed types for sets) just work.  
Alternatives rejected: replace local facts with accepted+corrs on success (would lose facts appended mid-flight + violate "client authoritative" until sync); always concat everything from resp (risk dups in facts[] array for debug/preview, even if project ok); complex pending queue separate from facts (over-engineering vs current append-only source of truth).  
This is robust, simple, matches "client can append the accepted + corrections" (we optimize to corrs only since accepted subset of what we sent).

**Decision: enhance existing OfflineBanner + add minimal sync state to QuestPlayerClient reducer (no new components or extraction unless bloat forces).**  
Rationale: Current banner already focused + receives onSimSync; per react "small focused (e.g. SyncButton or enhance OfflineBanner/ existing)", "no god". Add to PlayerState: isSyncing: boolean, syncError: string|null, lastCorrMessage: string|null . Reducer cases 'setSyncing', 'setSyncResult' (for error or corr msg). Handler rename internal to handleSyncClick (keeps onSimSync prop name for minimal banner change). In client: <OfflineBanner ... pendingCount={facts.length} isSyncing={isSyncing} corrMessage={lastCorrMessage} onSimSync={handleSyncClick} /> . Banner: if (isSyncing) 'syncing...'; else if (corrMessage) show it + timeout clear; show facts count or "pending N" when !sim; keep checkbox + "simulate sync" label exactly (simOffline still disables real path + forces alert path). Derived pending always from facts.length (no extra state). All in render or narrow handlers.  
On success clear error/corr after show; on error set syncError.  
This reuses 100%, keeps banner tiny, explicit conds.  
Alternative: extract <SyncStatus /> new file (rejected: YAGNI, would be 3rd tiny file for 1 interaction; enhance is KISS).  

**Decision: TDD via goldens extension in player-replay.test.ts (mock reconnect apply) + manual oneshot via dev server; no new test file unless duplication proven.**  
Rationale: "Goldens + replay are the TDD contract" (briefing); replay already loads happy + builds facts + asserts + edges + LS sim. Extend with: after happy facts, simulate "offline pending", build mock SyncResponse {corrections: [ {type:'balance_corrected', step_position:1, coins_delta: +3, reason:'overdraft_on_hint', device_id:.., note:null } ], projected: {balance:8, ...}, accepted:[] }, then "apply" by facts.push( normalize(mockCorr) ) or call a test helper applyCorrections(facts, corrs), re-assert projectBalance === authoritative, state includes, then JSON LS roundtrip + re-project still good. Cover happy reconnect (corrs=[]), overdraft corr case from facts-sync spec. Run `npx tsx ...` remains the verify. For real: tasks include "with backend running, manual play offline then sync from /quest". Keeps single test harness, goldens drive corr cases exactly (no backend dep for unit).  
Alternative: new reconnect.test.ts (possible later; YAGNI now, replay already the fidelity contract). Backend oneshot pattern reused only in archived; here frontend tsx sufficient.

**Decision: API endpoint + fetch minimal (hardcoded base + native, no AbortController/timeout/retry in v1).**  
Rationale: No new deps (explicit), native fetch always available. Use const API_BASE = typeof window !== 'undefined' ? 'http://localhost:8080' : ''; then `${API_BASE}/api/attempts/${attemptId}/facts`. Body JSON.stringify({facts: pending, snapshot_id: goldenId}). Content-Type. try { const r=await fetch...; if(!r.ok) throw; const resp = await r.json() as {accepted,corrections,projected}; ... } catch(e){ dispatch error }. Comment: // Demo: requires backend on 8080 (see tasks + archived backend-facts-sync). Relative '/api' would 404 in next dev (no proxy); full allows separate servers as current monorepo (concurrently). Snapshot_id sent (per AppendRequest).  
No SWR etc (YAGNI per react 4.x + briefing "no new"). Narrow effect not needed (handler in event).  
Survives: errors keep local authoritative (per TECH "client authoritative").

**Decision: Fact extension in shared-model.ts is additive only (union type string + optional fields); projectors untouched.**  
Rationale: To type-safely append corrs from server JSON without `as any`, extend: type FactType = 'physical_confirmed' | ... | 'balance_corrected' | 'version_mismatch_corrected'; interface Fact { type: FactType; step_position: number; submitted_value?: string | null; local_is_correct: boolean; coins_delta: number; note?: string | null; device_id: string; reason?: string; expected_snapshot?: string; /* for mismatch */ }. projectBalance already reduces any coins_delta; projectState ifs only on specific types (others no-op for sets) — identical to Rust match _ => {}. Goldens JSON + replay pushes use only old fields, stay valid. No behavior change. Matches archived facts-sync design note "extensions for corrections ... additive and do not alter".  
In proposal we listed no "Modified Capabilities" for shared-model-goldens (reqs unchanged).  
Alternative: separate CorrFact interface + union for facts (more code, YAGNI for small N).

All decisions reference exact contract (SyncResponse/AppendRequest), goldens (happy + "МИХАЙЛО ПУПИН"), prior artifacts, react.md (derived render, narrow, explicit), YAGNI (send full, enhance not extract, sim preserved, demo id).

## Risks / Trade-offs

[Fact shape drift between TS interface and Rust enum on future corr variants] → Mitigation: normalize always fills optionals; projectors are tolerant (sum/ignore); tests use real golden + injected corr from spec scenario; on apply of this change, replay will assert roundtrip of corr facts. If backend adds field, client optional accepts.

[Race: user appends fact while POST in flight (or page unload)] → Mitigation: send snapshot of facts at click; only corrs appended on return (new local facts + corrs coexist); append-only + idemp server means no loss/double-coin; no lock needed (local single-threaded). Unload during: facts already in LS, next load + reconnect will re-send (idemp).

[Demo attemptId + port coupling for "real" test from ctor "Save+open"] → Mitigation: fixed per-golden is explicit + documented in code/comments/tasks; "re-verify with real backend if running" in tasks; sim toggle allows full offline test without backend; no prod impact (future real attempt creation will replace the demo value).

[Minimal error/corrected UX (banner text only, no retry button, no visual "delta applied" on coins)] → Mitigation: YAGNI per explicit briefing ("no deep UI for "corrected" banner beyond simple (or reuse existing)", "simple"); existing completion screen + debug <pre>facts already shows post-sync authoritative; banner can show "balance corrected +3" briefly + auto-clear via timeout in setBonus style; future slice can enhance.

[During-sync UI (4-role nav/feedback still work, but btn disabled)] → Mitigation: set isSyncing disables the sync btn only; all other handlers (append, popup, menu) unaffected (facts grow, derived updates live); per PLAN "4-role/feedback/nav still work mid-sync".

[Extending shared Fact + LS payload shape (add attemptId)] → Mitigation: additive (old LS without attemptId will set demo value on load, no crash); JSON.parse tolerant; replay test LS sim uses extraFacts (no id needed); old saved state from prior player-pwa continues to work (step/facts only).

[No backend running -> real sync always fails in dev "Save+test"] → Mitigation: sim toggle + alert path always works; tasks require "ensure backend running for full manual"; error path explicitly keeps local + shows banner (proves "still authoritative"); goldens/replay cover the apply logic unit.

[Self-crit on overall wiring after rebuild]: The approach (enhance not refactor, send-full + only-corrs, normalize, fixed demo id, replay-ext TDD, banner enhance) survives adversarial scrutiny: uses exact backend contract + goldens for fidelity (happy + overdraft corr from archived spec), idemp safe (no client dedup needed), corrections folded into append-only log + LS + re-project (converges to authoritative), YAGNI (no grants, keep sim, small, no new deps), react compliant (RSC shell, narrow 'use client', derived in render, explicit), SOLID (pure shared, thin handler, focused comps), DRY (reuse project/append/LS 100%), KISS (concat, native fetch). Edges covered (concurrent appends, reload mid, multi reconnect, shape, error). Elegant:  minimal diff to existing reducer/effects/imports. Flaws remain (fetch UX barebones, no version UI, port manual, no timeout — all acceptable YAGNI per briefing/PLAN cuts; real grants later will layer on top without change to this flow). Survives because "client authoritative + server corrections" is the invariant, proven by projectors + TDD. Ready for specs (deltas on reconnect/ offline req) + tasks (20+ small, RED test first).
