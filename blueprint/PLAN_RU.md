## Фаза 2 — Shared типы, чистые функции, Goldens
- Определить и реализовать shared типы (сначала technology-agnostic, затем language-specific):
  - Expanded GameStep (completion + supporting с navigator/physical_action/bonus_animation + media roles).
  - Шейпы AttemptFact / CoinFact / FeedbackReport.
  - QuestDraft, QuestVersionSnapshot, AccessGrant и т.д.
- Чистые, heavily testable функции (один и тот же код используется конструктором, плеером, тестами, packer бандла):
  - isAnswerCorrect(submitted, acceptableList) — точные клиентские правила матчинга.
  - validateForPublish(draft) → {errors, warnings, estBundleMB}.
  - serializeToSnapshot(draft) → точная форма бандла.
  - projectState(facts) / projectBalance(facts) — детерминированный fold (клиент и сервер должны совпадать точно).
- Golden fixtures из реально экспортированных квестов:
  - Симулировать полные прохождения, упражняющие 4 шаблона, кнопку навигатора + кратчайший маршрут, неправильные ответы → обмен подсказки через попап, анимированные+озвученные бонусы, mid-quest FeedbackReport, сброс, факты multi-device, дрейф версии, долгий оффлайн.
  - Утверждения: корректные проекции, нет потерянных/двойных фактов, используются замороженные суммы снапшота, исход клиентского матча == записанному, повтор производит идентичную историю.
- Property-based и adversarial тесты для гонок (concurrent устройства, сброс concurrent с игрой, овердрафт при reconnect, публикация версии пока попытка активна).

## Фаза 3 — Срезы реализации (в порядке приоритета)
- Конструктор (admin/quests/constructor):
  - Форма метаданных + сортируемый список шагов.
  - Пикер 4 шаблонов (имена клиента: Первый экран, Задание без ответа, Задание с ответом, Продолжить), который pre-fills mode + supporting + текст кнопки/копию подтверждения.
  - Per-step редактор со structured AnswerListEditor + «Вставить строки» + live «Test match» (exact клиентская fn).
  - Subform подарка (нарратив + число монет + заметка «это замораживается в снапшоте»).
  - 4-role зоны загрузки комиксов (task/character/hint/atmosphere) + thumbnails.
  - Geo picker навигатора + toggle «включить кнопку навигатора (опциональная подсказка / кратчайший маршрут)» (видим на physical/Task-no).
  - Назначение ассетов анимации/голоса для бонусов заданий.
  - Wiring попапа подсказки (по умолчанию для заданий с ответом).
  - Per-step mini-превью (настоящий shared player компонент против текущих значений черновика).
  - Pre-publish чеклист + гейты (primary комикс обязателен для Task-шаблонов, валидное количество ответов, geo sanity, оценка размера, предупреждение об отсутствии терминала и т.д.) + «dry-run serialize».
  - Явная большая кнопка Publish, которая создаёт неизменяемый снапшот и триггерит материализацию бандла.
  - «Сохранить + открыть в реальном плеере как тестового пользователя» (сохраняет черновик, создаёт temp grant, открывает реальный flow PWA, упражняющий полный клиентский UX: попап, навигатор, аним/голос, any-page «Оставить отзыв», трата на рейтинг).
  - Вкладка импорта (вставка YAML/JSON или файл → strict parse/validate → загрузка в список). «Экспорт текущего как YAML».
  - Маленькие сфокусированные компоненты, shared рендереры с плеером, без god-объектов.
- Игрок / Опыт квеста (PWA):
  - Рендер шагов по 4 шаблонам.
  - Локальная валидация против встроенных списков acceptable.
  - UI физического подтверждения (uniform + опциональная заметка действия + кастомный текст кнопки из контента).
  - Ввод ответа + submit → при ошибке: немедленный попап «Потратить X на подсказку?» (единственный способ купить подсказку в v1).
  - Кнопка навигатора на Task-no / физических шагах (device maps:// или in-app с использованием bundled geo; опция gated_by_hint).
  - Анимированные + озвученные награды бонусов при достижении подарка или терминала.
  - Глобальное меню доступно на каждой странице (включая mid-quest) с «Оставить отзыв» (FeedbackReport с контекстом шага).
  - Post-completion flow Review (оценка + комментарий, опциональная трата монет для буста).
  - Локальный лог событий + проекция в оффлайне.
  - Индикатор «Режим оффлайн» + статус pending sync.
  - При подключении: загрузка pending фактов, получение авторитетного состояния + коррекций (чёткие баннеры: «баланс скорректирован», «подсказка отменена»).
  - Путь скачивания бандла, кэширования и повторного скачивания для исторических снапшотов.
- Sync / Прогресс бэкенд:
  - Append-only лог фактов (AttemptFact + CoinFact + факты FeedbackReport).
  - Идемпотентный endpoint append (по fact_id + естественным ключам).
  - Проекторы для текущего состояния QuestAttempt, баланса игрока, аналитики per-version.
  - Протокол коррекций (явные compensation facts для овердрафта, дубликата, mismatch версии и т.д.).
  - Хранение исторических снапшотов + manifest для повторной материализации.
  - Мерж multi-device по фактам (union).
- Коммерция / Маркетплейс:
  - Пожизненный AccessGrant (идемпотентный, с аудитом источника).
  - Checkout одного квеста + купон % (включая 100%).
  - Бесплатные квесты (идентичная механика).
  - Маркетплейс как peer компонент: списки опубликованных квестов с primary комиксом + summary по шаблонам; flow публикации выводит их туда; гранты/покупки проходят через поверхность.
  - Опциональный per-dl «download ticket» для более сильного оффлайн binding/аудита (если выбран).
- Видимость для админа:
  - Stats per-version (гранты, попытки, completion rates, отправленные неправильные ответы, использованные подсказки, клики навигатора, FeedbackReports per step).
  - Список FeedbackReports per quest/version (read-only для авторов).

## Фаза 4 — Полировка, миграция, измерение
- Импорт/экспорт в конструкторе (YAML предпочтителен) как power path для bulk операций и миграции.
- Аналитика per-version, surfaced в ctor и админ-вью.
- Миграционная задача (одноразовая, идемпотентная): исторические гранты + данные answer_card → синтетические legacy-снапшоты + факты. Аудит diff-ов против старых scalars. Пометить imported элементы.
- Измерять (post-MVP где возможно):
  - Реальные размеры бандлов с актуальными комиксами + аудио + данными навигатора.
  - Скорость конструктора и уровень дефектов с новыми визуальными/UX полями и гейтами.
  - Уровень коррекций sync.
  - Фидбек игроков на any-page «Оставить отзыв», кнопку навигатора, UX попапа подсказки, анимированные бонусы.
  - Паттерны abuse на трате на рейтинг (если включено).
- Обновлять инварианты и 08_DECISIONS_LOG с любыми новыми learnings. Перезапускать adversarial review, если клиентские данные или реальные экспорты квестов выявят новые edges.

## Явные cuts (v1)
- Нет покупки монет за реальные деньги.
- Нет внешних авторов.
- Нет magic links / сброса пароля для legacy-пользователей.
- Нет ветвления в квестах.
- Нет flows удаления данных / GDPR (не требуются).
- Нет multi-quest корзины.
- Нет recurring подписок.
- Нет high-fidelity live embedded превью в ctor при launch (save + real player test приемлемо).
- Нет продвинутой нормализации ответов при launch (базового membership достаточно).

## Риски, которые нужно проработать (из всех источников)
- Давление на размер бандла (4 роли комикса на страницу + озвученное аудио + данные навигатора поверх изображений/видео). Mitigation: опциональные роли, компрессия, гейт оценки размера в ctor, progressive loading где возможно.
- Скорость конструктора с добавленными полями (загрузка 4 ролей, навигатор, анимация, wiring попапа, визуальные гейты). Mitigation: шаблоны с хорошими дефолтами, пресеты, staged rollout более богатых фич, «test player» для быстрой валидации.
- Замороженный плохой контент (особенно визуалы и копия «опционального действия») живёт вечно для игроков, начавших на этой версии. Mitigation: усиленные pre-publish гейты + чеклист + mini-превью + аналитика per-version на отправленных неправильных ответах / репортах по шагу.
- Новое mid-quest состояние (траты через попап, использования кнопки навигатора, any-page FeedbackReports, триггеры анимированных бонусов, траты на рейтинг) создаёт дополнительные гонки sync. Mitigation: факты обязательны (без mutable состояния попытки), ключи идемпотентности, явные коррекции, контракт проекции клиент/сервер.
- Abuse траты на рейтинг (игроки фармят монеты на лёгких квестах, чтобы бустить рейтинги на платных). Mitigation: опционально / off-by-default, derived net-coins + reviews как primary сигнал рейтинга, per-quest лимиты при необходимости.
- «Опциональное действие» в физических шагах ощущается тривиально. Mitigation: богатый контент + кастомный текст кнопки + изображение задачи комикса + опциональные метаданные действия для дифференциации копии; всё равно uniform механизм подтверждения.
- Долг по propagation (meta-файлы обновлены, но первичные 01/03/04/00/06/07 ещё не отражают клиентское выравнивание и модель фактов). Mitigation: рассматривать этот план как обязательный перед детальной реализацией или решениями по tech stack.
- Всё ещё отсутствует валидация на реальных данных (повторяющийся gap по всем анализам). Mitigation: экспорт реальных квестов как первое действие в Фазе 1.
