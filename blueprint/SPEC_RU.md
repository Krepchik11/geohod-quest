# СПЕК

## Форма GameStep (основная модель данных)
GameStep имеет:
- Position (порядок внутри квеста; поддерживает переупорядочивание только в черновиках).
- Rich content (русский для v1): title / internal name, main_text (описание задания), place_text, варианты кнопок, prompt вопроса (когда применимо), durations, нарратив подарка, текст раскрытия подсказки, заметки автора (только в конструкторе, никогда в снапшоте).
- Media:
  - images: { task?, character?, hint?, atmosphere? } — в стиле комикса на страницу. Роль hint — это та, что раскрывается за монеты. Роль task обязательна для Task-шаблонов.
- Правило завершения (маленькие discriminated данные, замороженные в снапшоте):
  ```
  completion: {
    mode: 'physical' | 'answer',
    acceptable?: string[],   // только для режима answer; простой список из конструктора
    allow_note?: boolean
  }
  ```
  - 'physical': игрок выполняет явное подтверждение («Я сделал / Нашёл / Выполнил действие») + опциональная короткая заметка. Нет списка acceptable. Доверяем честности игрока. «No difference» между физическими шагами в механизме (богатый окружающий контент + кастомный текст кнопки + изображения обеспечивают дифференциацию).
  - 'answer': игрок отправляет значение; клиент делает membership match против списка acceptable (простая версия; продвинутая нормализация отложена).
- Поддерживающие / аддитивные поведения (валидируются при authoring, замороженные суммы):
  - gift?: { coins: number, narrative_text: string }
  - hint?: { cost_coins: number, reveal_text?: string, reveal_geo?: boolean }
  - navigator?: { lat: number, lng: number, label?: string, hint_only?: boolean, shortest_route_hint?: boolean }
  - bonus_animation?: { asset_ref: string, voice_ref?: string }
  - physical_action?: { description: string, confirm_label?: string }  // опционально для различия «перемещение + действие»
  - media_video?, terminal?, narrative_advance?, is_start?

Всё вышеперечисленное (список acceptable, подарочные монеты, стоимость подсказки и т.д.) замораживается дословно в снапшоте квеста в момент публикации. Старые попытки используют ровно те данные из своей привязанной версии.

## Четыре шаблона (основное отображение UI)
- First screen: старт / приветствие (обычно narrative_advance или is_start).
- Task no answer: физическое / перемещение + опциональное действие (completion mode = physical).
- Task with answer: вопрос / ввод (completion mode = answer).
- Continue: нарративный мост / терминальный (narrative_advance или terminal с prompt на review).

Конструктор должен поддерживать пикер для этих четырёх (с разумными pre-fills для текста кнопки, копии подтверждения и т.д.). Более богатая поддержка (подарок, навигатор, анимация и т.д.) разрешена поверх них.

## Ответы
- Конструктор предоставляет список допустимых строк (синонимы, числа, фразы) через простой multiline ввод (по одной на строку) или structured редактор.
- Клиент выполняет базовый membership / contains match против списка из локального снапшота.
- Точная функция матчинга, используемая в живом плеере, должна быть той же, что используется в live «Test match» боксе в конструкторе для этой версии.

## Физические шаги
- Uniform явный механизм подтверждения для всех физических шагов («no difference» в v1).
- Опциональная короткая заметка игрока.
- Опциональные метаданные действия (description + confirm label), чтобы захватить «перемещение + иногда выполнить конкретное действие».
- Geo — только для отображения (pin на карте). «Показать на карте» может быть раскрыто через трату монет на подсказку.
- В v1 не требуется цифровое доказательство. Доверяем честности.
- Нет цифрового proof в v1.

## Подсказки
- Основной (и в v1 единственный) триггер — попап неправильного ответа на заданиях с ответом.
- После неправильного сабмита → немедленный попап: «Потратить X монет на подсказку?»
- Использует per-step supporting.hint.cost.
- При обмене: списать монеты, раскрыть (изображение/роль подсказки, текст, geo или данные навигатора в зависимости от шага).
- В UI плеера нет отдельной всегда видимой кнопки подсказки ни в одном из четырёх шаблонов (попап — это механизм).

## Монеты / Экономика
- Заработок происходит исключительно из:
  - Подарков, определённых внутри GameStep (сумма заморожена из привязанного снапшота на момент публикации).
  - Канонических бонусов за завершение (например, 5 монет на терминале; first-only per player+quest через идемпотентность).
- Замороженные в снапшоте суммы: попытка, начатая на v1, всё равно использует значения подарков v1, даже если живой квест позже изменился.
- Траты: per-step, 1:1 с StepCompletion (в основном подсказки через попап).
- Per-attempt трекинг потраченных монет.
- Мастер-баланс игрока = сумма всех фактов заработка минус все факты трат (глобальная проекция).
- Анимированные и озвученные при награде (supporting.bonus_animation с asset и опциональной voice reference).
- Монеты также можно потратить (опциональный post-quest flow) или накапливать для персонального рейтинга игрока.
- В v1 нет ручных корректировок баланса администратором.
- В v1 нет покупки монет за реальные деньги.

Факты для монет унифицированы с фактами прогресса (или эмитируются связанными на записи StepCompletion). Ключи идемпотентности предотвращают double-earn. Коррекции (овердрафт и т.д.) — это явные compensation facts.

## Обратная связь
- FeedbackReport (тонкая append-only сущность):
  - Доступна из глобального меню на каждой странице / во всех четырёх шаблонах (даже mid-quest).
  - «Оставить отзыв» — в первую очередь для сообщения об ошибках/багах.
  - Автоматически прикрепляет текущую позицию шага, квест, контекст попытки.
  - Синхронизируется как другие факты (работает в оффлайне через локальную очередь).
- Review (отдельный):
  - После завершения квеста (на терминале или конце квеста).
  - Оценка + опциональный комментарий.
  - Может быть boosted через опциональную трату монет (RATING_SPEND факт).
- Оба видны администраторам per version / per step для улучшения качества (важно, потому что снапшоты заморожены).

## Содержимое бандла (для оффлайн-игры)
Полные упорядоченные GameStep, включая:
- Весь богатый контент и изображения по ролям комикса (task/character/hint/atmosphere).
- Простые списки acceptable ответов (встроены для клиентского матчинга).
- Замороженные значения поддержки (подарки, стоимость подсказок, данные навигатора, refs анимаций).
- Version / snapshot id + информация о целостности.
- Медиа (минимум изображения; короткие видео, когда есть).

Клиент должен уметь рендерить полную последовательность, делать локальную валидацию, тратить монеты на подсказки (попап), использовать данные навигатора, проигрывать анимированные/озвученные бонусы и поддерживать локальную проекцию баланса монет, находясь полностью в оффлайне.

## AccessGrant
- Player + Quest.
- Пожизненный (без срока действия в v1).
- Зафиксирован источник для аудита (Payment, CouponRedemption, FreeQuest, Admin).
- Требуется перед create Attempt или download бандла.
- Идемпотентное создание.
- Переживает новые версии квеста.

## Коммерция v1
- Только покупка одного квеста (без корзины).
- Купоны = процентные скидки (поддерживаются разные проценты; 100% купон = бесплатно через купон).
- Бесплатные квесты = идентичная механика с платными (просто добавляются в коллекцию, price 0 или явный флаг is_free).
- Одноразовый checkout.
- Грант создаётся при успешной оплате / купоне / бесплатном / от админа.
- Маркетплейс — peer top-level компонент (не просто thin supporting каталог). Опубликованные квесты появляются там с primary комиксом + summary по шаблонам; flow публикации выводит их туда; гранты/покупки проходят через эту поверхность.

## Заблокированные решения (из 08 + выравнивания по клиенту)
- Клиент полностью валидирует против своего снапшота; сервер записывает submissions + утверждение о локальном результате, но не выполняет re-validation корректности при синхронизации.
- Физические шаги: uniform явное подтверждение, «no difference», опциональная заметка. В v1 нет подтипов или разных UI завершения.
- Ответы: список строк через простой multiline (или structured редактор с live test). Базовый membership match.
- Превью конструктора: «Сохранить, затем переключиться на реального игрока как тестового пользователя» приемлемо для MVP. В launch не требуется high-fidelity embedded превью.
- Монеты: зарабатываются исключительно через игру (подарки, определённые в шагах + бонусы за завершение). В v1 нет ручных корректировок администратором, нет покупки монет за реальные деньги.
- Покупка: только один квест (без корзины).
- Импорт исторических грантов + истории попыток желателен (полностью per-step где возможно).
- Размер квеста: ~5 МБ на скачиваемый бандл (приемлемо для PWA оффлайн).
- Ветвление: нет в v1 (только линейная последовательность).
- Scope: события/календарь мёртвы. Только роли Administrator (internal) + Player. Только русский в v1. Legacy magic links/password reset не поддерживаются.
- Event-sourced факты для всего прогресса, монет, использований навигатора, подсказок через попап, mid-quest FeedbackReports, анимированных бонусов, трат на рейтинг.
- Требования клиента из «Описание сайта» являются авторитетными для UX/gameplay деталей и были инкорпорированы (3 компонента с Marketplace как peer, 4 шаблона как primary, комикс на страницу с 4 ролями, кнопка навигатора как опциональная подсказка с кратчайшим маршрутом, монеты за задания animated+voiced + тратить на hints или для rating, подсказки только через попап неправильного ответа без отдельной кнопки, «Оставить отзыв» из меню на любой странице для ошибок + отдельная оценка/коммент после).

## Антипаттерны старой системы (не повторять)
- Изменяемый контент под активными игроками.
- 14 вариантов Page_type + 36-полевые мультиязычные мешки + self-referential Next_page/Hint.
- 1163 workflow (в основном ButtonClicked + SetCustomState + прямые мутации).
- answer_card как per-user+step мешок флагов (Buy_hint, Complited и т.д.).
- Разбросанная логика монет («steps_for_accruing_coins_», запланированные процессоры «666»).
- Нет версионирования, нет снапшотов, нет дизайна для оффлайн.
- Дублированные «page» vs «page_constructor», «quest» vs «quest_name_constructor».
- Денормализованные списки на User, загрязняющие модель.

## Заметки по миграции (высокий уровень)
- Старые гранты (buy_a_qest, платежи, купоны, free, списки пользователя) → факты AccessGrant + проекции.
- Старые данные answer_card + списки пользователя + Balance_coin + Getting_5 list + Gift_Coins из page_constructor + countCoinMadeIt квеста → синтетические legacy-снапшоты (контент на момент экспорта) + StepCompletionFacts + CoinFacts (по возможности сохранять отправленные значения и приблизительные timestamps).
- Одноразовая идемпотентная задача. После импорта новая система чистая. Legacy-элементы помечены «imported». Старый scalar баланс сверяется через diff лога (ручной review, без auto-adjust).

## Концептуальные тесты / Goldens (обязательно)
- Golden fixtures из реальных квестов: экспорт page_constructor с Gift_Coins, симуляция полных прохождений (включая 4 шаблона, использование навигатора, неправильные ответы, триггерящие попап подсказки, анимированные бонусы, FeedbackReports, сброс, multi-device факты, дрейф версии, долгий оффлайн).
- Утверждения: корректные проекции, нет потерянных/двойных фактов, используются замороженные суммы снапшота, исход клиентского матча == записанному, повтор производит идентичную историю.
- Идемпотентность: дублированная sync/upload одного и того же завершения или подарка → только один факт.
- Сценарии гонок (property-based или adversarial): concurrent игра на двух устройствах, сброс concurrent с игрой, публикация версии пока попытка в процессе, долгий оффлайн + несколько подсказок/подарков, овердрафт при reconnect.
- Заморозка версии: завершение на снапшоте v1 всё равно использует gift-значения v1 даже после изменения живого квеста.
- Fidelity проекции клиент/сервер: локальный fold на бандле должен точно совпадать с серверным fold.
- «Hard to publish bad»: гейты отвергают или предупреждают об отсутствии primary комикса для Task-шаблонов, нулевом количестве ответов, невалидном навигаторе и т.д.

Всё вышеперечисленное должно быть enforceable в типах, unit-тестах, integration-тестах и CI.
